Gateway API Ingress controller:
--------------------------------------

The Gateway API is the next generation networking API for kubernetes, designed to replace and improve upon the traditional ingress API.

Advantages:
---------------
1. Better traffic routing ( HTTPRoute, TCPRoute, GPRCRoute )
2. Role oriented configuration
3. Multi Tenancy configuration
4. Traffic splitting 
5. Header based routing 
6. http , https, tcp, udp, grpc, mtls 
7. Extensible architecture

Ingress resources + controller

ingress.yaml + route (rules)


Main components of Gateway API
--------------------------
Resources:
------------------
1. GatewayClass ---> defines the Gateway implmenetation
2. Gateway ---> entry point for the traffic
3. HTTP ROUTE ---> Http traffic rules

4. TCP Route---> Tcp traffic routing
5. TLSRoute ---> TLS traffic routing ( https , http-->https )
6. ReferenceGrant ---> Cross namespace access

Nginx Ingress controller ---> less feature ---> HTTP only scope . 

TCP, GRPC, MTLS, header based routing, cross namespace delegation, advance traffic policies

Ingress controller --> Nginx -F5 Nginx Ingress controller

Kubernetes CNCF --> Ingress Nginx controller

Traefik --> Traefik Ingress controller

ingress.yaml ---> IngressClass, Routing rules, annoatations


Gateway API 
---------------------------
Gateway API + Nginx fabric controller

Gateway API + Traefik controller

GatewayClass ---> it defines the load balancer

Gateway --> defines the listeners ( Ports, protocol, TLS termination )

Routes (HTTPROUTE, HTTPSROUTS, GRPCROUTE .... ) defines the routing rules

Policies ---> attach behaviours ( timeouts, retries, auth etc )
