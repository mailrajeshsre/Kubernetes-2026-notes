Gateway API - grpc based routing 


Gateway API crds + controller==> functionality of Gateway API 

Nginx Fabric ---> HTTP Route + GRPC Routes 
Traefik controller -> HTTP/HTTPS Route, TLS Termination, GRPC based routing , Header
kong controller
Envoy-Gateway-controller --> HTTP/HTTPS Route, TLS Termination, TCPRoute ,GRPC based routing 
Isito Controller - Advance controller -> HTTP/HTTPS Route, TLS Termination, GRPC based routing + Advance feature 


Gateway API supports gRPC traffic routing using GRPCRoute resources , this allows routing gRPC service based on function , method , hostnames and headers similar to what we see in HTTP Routing

2. Gateway API - CRDs

How the developers write the code using grpc service


Proto type:
-------------------------

service UserService {
    rpc GetUser ( GetUserRequest)
	     return (UserResponse);
}

service OrderService {
     rpc GetOrder ( GetOrderRequest )
	     returns (OrderReponse);
}

Backend Services:
-----------------------
Service:
   user-grpc-service
   
Service:
    order-grpc-service
	
GRPCRoute:
-----------------------------
hostnames:
  - "grpc-gateway.com"
rules:
  - matches:
      - method:
          service: UserService
          method: Ping
    backendRefs:
      - name:user-grpc-service
        port: 50051
        weight: 1
  - matches:
      - method:
          service: OrderService
    backendRefs:
      - name: order-grpc-service
        port: 50051
		
		
Traffic flow:
-------------------------------


http://grpc-gateway.com/UserService/* ---> user-grpc-service

http://grpc-gateway.com/OrderService/* --->order-grpc-service

GRPCRoute complete capabilites
---------------------------

1. Host based routing 

2. Method based routing 

3. Header Matching

4. Traffic splitting ( Weight based routing )

5. TLS Termination ( HTTPS --- self signed certificate)

6. Canary Deployment / Blue Green deployment 

7. Multi service Routing
